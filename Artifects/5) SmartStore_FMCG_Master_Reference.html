Modules Missing From UI Not Built

⚠
These 6 modules were identified from FMCG gap analysis. They have no screen at all in the current HTML file. They need to be designed and built from scratch — both UI and backend.
1 — Returns & Exchange
Customer returns, damaged goods processing, credit note generation. Without this, a shop can never handle a customer returning a product — a daily occurrence in FMCG retail.
2 — Supplier Rating
On-time delivery scoring, price consistency tracking, quality feedback from PO/GRN data. Helps buyer know which suppliers to prefer when reordering.
3 — Customer Loyalty / CRM
Loyalty points accumulation, membership tiers (Silver/Gold/Platinum), repeat customer tracking, purchase history analysis. Needed to compete with modern retail apps.
4 — GRN / Delivery Tracking
Inward goods receipt with item-level verification, shortage claims for bulk deliveries. The Purchase module exists but GRN workflows are only partial — no dedicated screen for receiving goods against a PO.
5 — Print Invoice
Thermal printer layout (58mm/80mm) for POS receipts, A4 GST invoice PDF for dealer billing. Currently there is no print screen or PDF generation — critical for any real business use.
6 — Multi-Location / Godown Manager
2-3 godown inventory sync, location-wise stock transfer, per-location stock reports. Inventory module references multi-location but there is no dedicated godown management screen.

Tech Stack Decided

HTML Frontend (18 Modules) → fetch() JSON API calls → FastAPI Backend (Python) → PostgreSQL Database
Layer Technology Reason
API Server FastAPI (Python) Auto-generates Swagger docs at /docs; async; Python = same language for AI + integrations
Database PostgreSQL DECIMAL type = no floating-point GST errors; ACID transactions; free and open source
Authentication JWT Tokens 3 roles: owner / cashier / staff — enforced at every API endpoint
Offline / PWA Service Worker + IndexedDB Works without internet; Background Sync pushes queued transactions on reconnect
File Storage Local Disk or S3 Product images, invoice PDFs — local disk for small deployments, S3 for scale
Real-time Updates WebSocket Live KPI dashboard — sales totals update in real time as POS bills are created
Hosting Any VPS (Linux) DigitalOcean / Hetzner / Contabo — 2GB RAM is enough. Rs 500-800/month.

Why FastAPI + PostgreSQL Was Chosen

  • Python = same language for backend, AI forecasting, and all integrations (Razorpay, Gupshup, Tally XML, NIC portal)
  • FastAPI auto-generates Swagger /docs — built-in API documentation for every endpoint
  • PostgreSQL DECIMAL type eliminates floating-point rounding errors in GST calculations
  • Python developers are 3x more available in India compared to Node.js developers
  • All required libraries exist: razorpay, gupshup-python, reportlab (PDF), lxml (Tally XML)
  • ERPNext was rejected: too heavy, too complex, Frappe framework locks you in, hard to customize

Deployment Strategy Decided

✓
Decision: Cloud + Offline PWA — NOT a traditional desktop app
The app will be hosted on a Rs 500-800/month VPS, but will work offline using Service Workers and IndexedDB. It installs on PC and phone like a native app via PWA manifest.

How Offline Works

  • Service Worker caches the entire app shell locally — app loads without internet
  • IndexedDB stores all new transactions locally when WiFi is unavailable
  • Background Sync API automatically pushes all queued transactions to the server when WiFi returns
  • PWA Manifest makes the app installable on Windows PC and Android phone — looks and feels like a native application
  • Same Rs 500/month server — no extra cost for offline capability

Our Play:"Same FMCG features. Modern app. Honest pricing. Support that actually responds."
Tally Prime Accounting Dominant — 70+ lakh licenses
Strengths:70+ lakh licenses. CAs and accountants default to recommending it. Deep accounting compliance. Widely trusted.
Weaknesses:Zero mobile, zero cloud, zero AI. Complex UI for non-accountants. No FMCG-specific workflows (expiry, wastage, dealer credit).
Our Play:"Don't replace Tally for accounting — integrate with it. Keep Tally for your CA, use SmartStore for everything else." Tally XML export is a critical feature to retain CA buy-in.
Vyapar Mobile Billing — 1 crore+ users
Strengths:1 crore+ users. Simple mobile billing. UPI-first. Excellent for very small businesses.
Weaknesses:Hits a ceiling at Rs 2-5 crore revenue. No real inventory management beyond basic stock count. No multi-location, no dealer credit (Udhaar), no expiry tracking.
Our Play:"You've outgrown Vyapar. Same simplicity, 10x the capability." Target Vyapar users who are growing.
Zoho Inventory Cloud ERP — Per-user pricing model
Strengths:Polished cloud product. Good integrations. Strong brand recognition.
Weaknesses:No offline capability — useless during internet outages. Per-user pricing kills scaling: 20 users = Rs 3 lakh per year. Not FMCG-specific (no expiry, wastage, dealer credit).
Our Play:Flat pricing model — no per-user charges. Works offline. Built specifically for FMCG not generic inventory.
PetPooja Restaurant POS — UX Benchmark (1,00,000+ outlets)
Strengths:Solved the hardest problem in Indian B2B software: getting a non-technical shop floor worker to use software daily. Color-coding, single-screen operations, offline-first, voice input, WhatsApp-native.
UX Lessons:Color-code everything for low-literacy workers. Keep key actions on ONE screen. Offline must work perfectly. WhatsApp is the preferred communication channel. Voice input helps non-typists.
Our Goal:SmartStore must be as simple as PetPooja for shop floor staff — especially cashiers and stock boys who are not tech-savvy.

Priority Build Order — What to Build Next

ⓘ
Build in this exact sequence. Each item unblocks the next. Do not skip ahead — building CRM before the basic backend exists is wasted effort.
  • FastAPI backend + PostgreSQL database schema
    Foundation for everything. All tables: products, inventory, sales, customers, suppliers, users. Without this, nothing else is persistent.
  • JWT authentication — owner / cashier / staff roles
    Login screen + token-based access control. Every API endpoint protected by role. Owner can see everything; cashier can only access POS and payments.
  • Service Worker + PWA manifest — offline capability
    Caches app shell. IndexedDB for offline transactions. Background Sync for reconnection. This is the core competitive differentiator — must be built early.
  • Connect POS Billing screen to real APIs
    Product lookup by barcode → API. Add to cart → API. Complete sale → API. This is the most-used feature — highest priority to make real.
  • Connect Inventory to real APIs
    Stock levels, FIFO costing, reorder alerts all driven by live PostgreSQL data. Expiry and batch tracking connected to real data.
  • Connect Dealers / Udhaar to real APIs
    Customer credit limits, outstanding balances, collection history — all persisted in database. This is a major pain point for Indian retailers.
  • Tally XML export
    Python XML generator for Tally-compatible export. Critical for CA acceptance. Removes a major sales objection.
  • Razorpay UPI integration
    Real payment collection in POS. UPI QR generation, payment status webhook, auto-reconciliation.
  • Real GST e-Invoice via NIC portal
    IRN generation for B2B invoices above Rs 5 crore turnover. Required for compliance. Python HTTP calls to NIC sandbox first, then live.
  • WhatsApp 2-way via Gupshup
    Customers can reply to payment reminders. Query their outstanding balance. Receive order confirmations. Turns the chatbot into a real customer service channel.
  • Build missing modules: Returns, Supplier Rating, CRM, Print Invoice, GRN, Godown Manager
    The 6 modules from Section 4 — design UI first, then build backend APIs for each.
